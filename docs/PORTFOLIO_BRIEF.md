## 왜 이 문제인가

- 국내 시각장애 등록 인구 **약 24만 7천 명** ([보건복지부 2024 등록장애인 현황](https://www.mohw.go.kr/board.es?mid=a10503000000&bid=0027&list_no=1485363&act=view))
- 조사에 응답한 시각장애인의 **77.1%**가 키오스크 편의 기능 미비로 이용에 어려움을 경험 ([보건복지부 조사 KDI 아카이브](https://eiec.kdi.re.kr/policy/materialView.do?num=269629))
- LG·삼성 등 기존 대안은 점자 스티커·음성 매뉴얼 수준 — 여전히 *정확한 위치를 사용자가 직접 터치*해야 함
- 스마트홈 가전 교체는 비용이 크고 기존 가전에는 적용 불가

**Touch Bridge의 차별점**: 교체가 아닌 **부착**으로 기존 가전을 그대로 접근성 있게 만듦.  
[UIST 2023 BrushLens](https://dl.acm.org/doi/10.1145/3586183.3606730)는 촉각 인터페이스 탐색 보조의 가능성을 보여주는 관련 연구이며, 그 결과를 Touch Bridge 자체 성능으로 인용하지 않음.

## 시스템 구조

```
사용자 음성
    ↓
Flutter 앱 (STT + Gemini AI)
    ↓ 논리 버튼 ID (BT-01, BT-02 ...)
BLE (Bluetooth Low Energy)
    ↓
ESP32 허브
    ↓ 엔코더 폐루프 PID
FIT0482 X/Y 모터 2개
    ↓ 위치 오차·토큰 확인
스위치봇 누름부
    ↓
가전 터치패드 물리적으로 누름
```

## 앱 핵심 기능 (현재 구현 상태)

### 1. 음성 명령 (STT + Gemini AI)
- 한국어 자연어로 가전 조작: "전자레인지 30초 돌려줘", "세탁기 표준 코스 시작"
- 지원 가전: 전자레인지 / 세탁기 / 에어컨 (ApplianceCommandRouter 자동 라우팅)
- 화면 이동 명령: "설정 열어줘", "기기 연결 화면"
- STT 침묵 타임아웃 개인 맞춤 조절 (5~15초)

### 2. 접근성 우선 UX (WCAG 2.2·플랫폼 지침 기반)
- **위험도 기반 확인**: 실제 작동·삭제 등은 첫 탭 안내 후 실행, 스크린리더의 단순 이동은 중복 확인 생략
- **비상 정지**: 버튼 3초 홀드 또는 음성 "멈춰" — 어떤 화면에서도 즉시 동작
- **TalkBack/VoiceOver 코드 수준 지원**: CustomSemanticsAction, liveRegion, ExcludeSemantics와 드래그 대체 버튼 적용; 실기 당사자 평가는 예정
- **200% 폰트 대응**: 시스템 글자 확대 설정 존중

### 3. 사용자 / 보호자 모드 분리
- 사용자 모드(기본): 홈·비상·설정만 — 시각장애인이 실수로 설정을 깰 수 없음
- 보호자 모드: 기기 추가·연결·매핑 활성화

### 4. BLE 연동
- ESP32 GATT 서버와 BLE 통신
- 자동 재연결 (지수 백오프 2→4→8초, 최대 3회)
- NFC 등록 지원; QR은 의존성 제거로 현재 비활성화하고 정직한 안내 표시

### 5. Gemini Vision 버튼 자동 매핑
- 가전 사진 촬영 → AI가 버튼 위치 자동 인식
- 네 모서리 보정으로 실제 X/Y mm 변환, 기기별 저장
- 드래그와 상·하·좌·우 대체 조작, 한 점씩 이동 검증 지원

## 포트폴리오에 강조할 포인트

1. **문제 기반 설계**: 정부 조사와 관련 HCI 연구를 구분해 인용하고 실제 사용자 평가 계획으로 연결
2. **복잡한 접근성 구현**: 의미 구조·라이브 영역·드래그 대체·스크린리더 중복 확인 완화
3. **AI 실용 활용**: Gemini Vision 결과를 4점 투영 보정과 검증 게이트를 거쳐 실제 mm 좌표로 변환
4. **1인 앱 단독 개발**: Flutter 앱 전체 + 백엔드 API 설계까지 단독 완성
5. **테스트 체계**: Flutter 306개·백엔드 3개 자동화 테스트로 회귀 방지
