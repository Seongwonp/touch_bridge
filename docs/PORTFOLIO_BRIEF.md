## 왜 이 문제인가

- 국내 시각장애 등록 인구 **약 24만 7천 명** (보건복지부 2024)
- 시각장애인의 **77.1%**가 키오스크·가전 편의 기능 미비로 이용에 어려움 (보건복지부 2024)
- LG·삼성 등 기존 대안은 점자 스티커·음성 매뉴얼 수준 — 여전히 *정확한 위치를 사용자가 직접 터치*해야 함
- 스마트홈 가전 교체는 비용이 크고 기존 가전에는 적용 불가

**Touch Bridge의 차별점**: 교체가 아닌 **부착**으로 기존 가전을 그대로 접근성 있게 만듦.  
물리 터치 대행 방식은 UIST 2023 BrushLens 연구에서 오터치율 **73.9% 감소** 효과가 검증된 접근법.

## 시스템 구조

```
사용자 음성
    ↓
Flutter 앱 (STT + Gemini AI)
    ↓ 논리 버튼 ID (BT-01, BT-02 ...)
BLE (Bluetooth Low Energy)
    ↓
ESP32 허브
    ↓ G-code
Arduino GRBL + 스텝모터
    ↓
가전 터치패드 물리적으로 누름
```

## 앱 핵심 기능 (현재 완성 상태)

### 1. 음성 명령 (STT + Gemini AI)
- 한국어 자연어로 가전 조작: "전자레인지 30초 돌려줘", "세탁기 표준 코스 시작"
- 지원 가전: 전자레인지 / 세탁기 / 에어컨 (ApplianceCommandRouter 자동 라우팅)
- 화면 이동 명령: "설정 열어줘", "기기 연결 화면"
- STT 침묵 타임아웃 개인 맞춤 조절 (5~15초)

### 2. 접근성 우선 UX (WCAG 2.2 AA/AAA + KS X 3253 준수)
- **이중 탭 확인**: 첫 탭 → 안내, 둘째 탭 → 실행 (20초 타임아웃, 오작동 방지)
- **비상 정지**: 버튼 3초 홀드 또는 음성 "멈춰" — 어떤 화면에서도 즉시 동작
- **TalkBack/VoiceOver 완전 지원**: CustomSemanticsAction, liveRegion, ExcludeSemantics 전 화면 적용
- **200% 폰트 대응**: 시스템 글자 확대 설정 존중

### 3. 사용자 / 보호자 모드 분리
- 사용자 모드(기본): 홈·비상·설정만 — 시각장애인이 실수로 설정을 깰 수 없음
- 보호자 모드: 기기 추가·연결·매핑 활성화

### 4. BLE 연동
- ESP32 GATT 서버와 BLE 통신
- 자동 재연결 (지수 백오프 2→4→8초, 최대 3회)
- QR 코드 스캔으로 기기 빠른 등록

### 5. Gemini Vision 버튼 자동 매핑
- 가전 사진 촬영 → AI가 버튼 위치 자동 인식
- 기기별 독립 저장, 수동 편집 가능

## 포트폴리오에 강조할 포인트

1. **문제 기반 설계**: 연구 수치(77.1%, 73.9%)를 근거로 접근성 우선 설계
2. **복잡한 접근성 구현**: WCAG 2.2 AAA 일부 준수, KS X 3253 22/24항목, TalkBack 완전 지원
3. **AI 실용 활용**: Gemini Vision으로 어떤 가전이든 버튼 자동 인식
4. **1인 앱 단독 개발**: Flutter 앱 전체 + 백엔드 API 설계까지 단독 완성
5. **테스트 체계**: 160개+ 자동화 테스트로 회귀 방지
