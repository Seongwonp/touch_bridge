```markdown
(2) 펌웨어 — GRBL의 리미트/ALARM 정지, (3) 물리 — 12V 모터 전원 분리·수동 차단.
매핑 테스트 시 "기기 주변에 손을 두지 마세요"를 강제 안내한다.

**Q. AI가 잘못 판단하면 기계가 엉뚱한 곳을 누르지 않나?**
A. AI는 논리 버튼 ID까지만 만들고 좌표는 만들지 않는다. 좌표는 보호자가 검증·저장한
매핑에서만 나오므로, AI 오류가 곧바로 잘못된 물리 동작이 되지 않는다. 모호하면 되묻는다.

**Q. BLE가 끊기거나 명령이 유실되면?**
A. 명령→응답 확인 기반 순차 전송이며, 실패는 즉시 음성으로 알린다.
연속 전송 신뢰성은 런북의 통신 검증 절차로 확인한다.

**Q. 왜 ESP32 하나로 통합하지 않고 Uno+GRBL을 유지하나?**
A. 검증된 모션 제어를 유지하면서 무선 계층만 추가하는 것이 개발 위험이 가장 작았다.
FluidNC 등으로의 통합은 로드맵에 있다.

**Q. 시각장애인 당사자 검증은?**
A. (진행 상황에 맞게 답할 것) "화면 가리고 완주" 합격 기준과 스크린리더 병행 시나리오를
런북에 정의했고, 접근성 실험 지표(완료율/평균시간/비상정지/타임아웃)로 정량 측정한다.
```
