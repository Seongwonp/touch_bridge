# Touch Bridge 심사 요약서

## 1) 문제와 대상
- 대상: 시각장애인/저시력 사용자
- 문제: 터치패널 가전(전자레인지 등)은 버튼 위치 확인이 어려워 오작동 위험이 큼

## 2) 해결 방식
- 앱(음성/수동)에서 명령 생성
- BLE로 ESP32 허브에 명령 전송
- 하드웨어가 실제 터치패드를 물리적으로 눌러 동작 수행

## 3) 차별점
- 접근성 UX 중심 설계
  - 이중 탭 확인(오작동 방지)
  - 비상 정지(홀드/음성)
  - TTS 피드백/큰 글씨/고대비
- 기기별 버튼 매핑
  - AI 사진 분석 + 3x3 매핑 저장
- 데이터 무결성
  - immutable `deviceId` 기반 저장/마이그레이션
- 보안
  - Gemini API 키는 백엔드만 보관(클라이언트 직접 보관 제거)

## 4) 현재 구현 상태(심사 기준)
- 완료
  - BLE 연동 1차: 스캔/연결/명령 전송
  - 음성 명령 파싱 및 전송 연계
  - 접근성 실험 지표 수집(완료율/평균시간/비상정지/타임아웃)
  - 테스트 자동화 10개 통과
- 고도화 예정
  - BLE 재연결 안정화
  - 센서 피드백(전류/온도) 수집 및 상태 모니터링

## 5) 정량 지표(시연 시 제시)
- 총 작업 수, 완료율, 평균 완료 시간
- 음성 작업 비율 / 수동 작업 비율
- 비상 정지 횟수
- 이중탭 타임아웃 횟수

## 6) 기대 효과
- 비시각 조작 가능성 향상
- 오조작/위험 상황 대응력 강화
- 고가 스마트홈 교체 없이 기존 가전 접근성 개선
