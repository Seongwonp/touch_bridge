# Touch Bridge — FIT0482 X/Y + 스위치봇 소프트웨어 고도화 계획

> 상태: 2026-09-04 M1~M5 앱 코드 완료, 펌웨어·실기·당사자 검증 진행 대기
> 목표: 사진에서 고른 버튼을 실제 X/Y 위치로 반복 이동한 뒤 스위치봇으로 누른다.

## 확정 방향

- X/Y: FIT0482 엔코더 DC 기어모터 2개
- 모터 제어: ESP32 폐루프 PID
- 원점: X/Y 리미트 스위치
- 누름: 별도 Z축이 아니라 스위치봇
- 앱은 모터 PWM을 직접 제어하지 않고 목표 mm 좌표와 명령 ID를 보낸다.
- AI가 만든 사진 좌표는 검토 전에는 물리 좌표로 간주하지 않는다.

## 단계별 좌표 모델

```text
사진 정규화 좌표(x, y: 0~1)
  -> 패널 기준점 4개로 왜곡 보정
패널 평면 좌표(mm)
  -> 장치 원점/축 방향/안전 범위 적용
장치 목표 좌표(Xmm, Ymm)
  -> ESP32의 mm당 엔코더 카운트 변환
엔코더 목표 카운트
```

행/열은 화면 정렬과 구형 데이터 호환에만 사용한다. 신규 실행의 기준은
`buttonMachinePositions[buttonId] = {xMm, yMm}`이다.

## 앱-ESP32 v2 명령 계약

앱 측 계약과 안전 상태 머신은 확정했다. 상세 규격은
[`ESP32_MOTION_PROTOCOL_V2.md`](ESP32_MOTION_PROTOCOL_V2.md)에 있다. 실제 런타임
전환은 ESP32 펌웨어가 동일 계약을 구현하고 실기 검증을 통과한 뒤 수행한다.

```json
{
  "version": 2,
  "commandId": "uuid",
  "action": "move_and_press",
  "deviceId": "microwave-1",
  "target": {"xMm": 42.5, "yMm": 18.25},
  "toleranceMm": 0.7,
  "pressActuator": "switchbot"
}
```

상태 응답:

```text
RECEIVED -> HOMING(optional) -> MOVING -> POSITIONED -> PRESSING -> COMPLETED
                                  |             |            |
                                  +-> ERROR_POSITION / ERROR_STALL / ERROR_PRESS
```

앱은 `COMPLETED`와 동일한 `commandId`를 받기 전에는 “완료”라고 안내하지 않는다.
재연결 후 상태가 불명확하면 자동 재실행하지 않고 상태 조회 후 사용자에게 확인한다.

## 구현 순서

### M1. 매핑 데이터 기반

- [x] 버튼별 실제 mm 좌표 저장 필드 추가
- [x] 실제 mm 좌표 우선 실행, 구형 그리드 좌표 폴백
- [x] Vision 응답에 정규화 중심 x/y와 confidence 요구
- [x] 낮은 신뢰도·중복·범위 밖 Vision 결과 서버에서 제거
- [x] 프로필 schemaVersion 및 마이그레이션 결과 로그

### M2. 4점 캘리브레이션

- [x] 사진에서 패널 모서리 4점 선택
- [x] 패널 좌상단 장치 좌표와 실제 폭·높이로 네 모서리 mm 좌표 등록
- [x] 투영 변환으로 모든 버튼의 X/Y mm 계산
- [x] 변환 후 작업영역·최소 간격·중복 좌표 검증
- [x] 사진 파일 크기·수정시각·경로 변경 시 기존 캘리브레이션 무효화
- [ ] 물리 프레임 이동은 기준 마커/센서 또는 설치 확인 절차로 감지

### M3. FIT0482 모션 계층

- [x] `MotionController`와 `PressActuator` 인터페이스 분리
- [x] ESP32 PID 앱 프로토콜 v2 확정
- [x] 홈 완료 전 이동 금지
- [x] 목표 오차가 허용값 이내이고 위치 토큰이 있을 때만 스위치봇 실행
- [x] 스톨·리미트·시간초과·통신 끊김 상태 정의
- [x] 비상 정지는 큐보다 우선하는 별도 BLE 경로로 처리
- [ ] ESP32 펌웨어 구현 및 실기 PID/ACK 검증 후 레거시 XYZ 실행 경로 교체

### M4. 안전한 매핑 검증

- [x] 전체 자동 누름 테스트 제거
- [x] 버튼 하나씩 음성 안내와 확인 창을 거친 뒤 테스트
- [x] 시작·취소·출력 등 위험 버튼 별도 확인
- [x] 누르기 전 위치만 확인하는 `move_only` 모드
- [x] 엔코더 오차와 보호자 실측 X/Y 오차를 기기별 최근 100회까지 기록

사진 매핑의 검증 기능은 v2 상태 머신을 사용한다. 화면에서 원점 설정이
확인되기 전에는 `move_only`와 실제 누름이 모두 차단되며, 실패도 검증 기록에
남는다. 일반 사용자 명령 경로의 v2 전환은 M3의 펌웨어 실기 검증 이후다.

### M5. 접근성 및 당사자 검증

- [x] 보호자 설치 흐름과 사용자 실행 흐름 명확히 분리
- [x] 촬영 전 카메라 정렬을 단계별 방향성 음성·진동으로 안내
- [x] TalkBack/VoiceOver에서 화면 이동 이중 확인 재평가
- [x] 드래그 기능에 버튼/조그 대안 제공
- [ ] 전맹·저시력 사용자를 분리 모집해 실제 과업 평가

설치·연결·사진/수동 매핑 화면은 제목에 `설치 모드`를 명시하고, 사용자 모드
하단 메뉴에서는 기기 관리 항목을 숨긴다. 단, 보호자 없이 사용하는 당사자의
독립 설치 가능성을 막지는 않는다. 화면읽기가 활성화된 경우 운영체제 자체의
선택 후 두 번 탭이 이미 있으므로 **단순 화면 이동만** 앱의 추가 확인을 생략한다.
실제 기기 작동과 삭제 등 위험 동작의 앱 확인은 그대로 유지한다.

사진 촬영은 현재 `image_picker` 구조상 실시간 프레임 분석이 아니며, 카메라를
열기 전에 뒤/좌/우/위/아래 이동과 수평·반사를 네 단계로 안내하는 방식이다.
실시간 자동 정렬 판정은 카메라 CV 도입 전까지 완료로 간주하지 않는다. 패널
모서리와 버튼 중심은 드래그 외에 0.5% 단위의 네 방향 버튼으로도 조정할 수 있고
매 조정마다 음성·진동 피드백을 준다.

관련 운영 로그: `mapping.camera_guide_step`, `mapping.camera_guide_completed`,
`mapping.camera_guide_cancelled`, `mapping.calibration_corner_nudged`,
`mapping.button_position_nudged`, `accessibility.navigation_confirmation_skipped`.

## 통과 기준

- 버튼별 30회 반복 이동에서 95% 이상이 중심 ±0.7mm 이내
- 잘못된 버튼 누름 0회
- 홈 미완료·위치 오류·스톨 상태에서 스위치봇 작동 0회
- BLE 재연결 후 중복 실행 0회
- TalkBack/VoiceOver만으로 기기 선택·명령·취소·상태 확인 가능
- 장애인 당사자 평가에서 비상 정지 성공률 100%
