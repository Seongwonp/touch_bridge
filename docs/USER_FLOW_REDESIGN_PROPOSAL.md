# 사용자 화면 흐름 재설계 제안 (2026-11-10)

상태: **제안**(9절 결정 반영). 아직 구현하지 않았다. 실기 TalkBack 확인과 시각장애인 당사자 과업 평가 전이므로 최종안이 아니다.

배경: TalkBack 사용자 관점 코드 리뷰(2026-11-10)에서 "혼자 전자레인지 작업 완료" 4/10이 나왔다. 정지·완료 문구, TalkBack 정지 탭 같은 개별 결함은 같은 날 고쳤다. 남은 문제는 구조다. 일상 조작, 보호자 설치, 개발자 점검이 한 앱에 섞여 있고, 확인 방식이 화면마다 다르다.

## 1. 지금 무엇이 섞여 있나 (코드 기준 사실)

| 문제 | 현재 코드 |
|---|---|
| 확인 방식이 5가지 | 앱 자체 두 번 누르기(20초, `primary_button`·`control_mode_sheet`·마이크), 음성 "예" 확인(`needs_confirmation`), 3초 길게 누르기(남은 시간 화면 정지), 단일 탭(누르는 중 화면 정지), 낭독기 사용자 지정 작업(`CustomSemanticsAction`) |
| 기기 선택이 좌우 넘기기 | `home_screen.dart` PageView. TalkBack에서는 넘기기를 잠그고 하단 버튼으로 바꾼다 |
| 제어 방식 메뉴에 보호자 기능 | `control_mode_sheet.dart`: 음성·이미지·간편 코스·숫자 패드 옆에 "좌표 매핑(보호자용)" |
| 설정 한 화면에 세 역할 | `settings_screen.dart`: 음성 안내·큰 글씨(사용자), 기기 추가·하드웨어 관리(보호자), 개발자 모드·통신 로그·지표 내보내기(개발자) |
| 안내 담당이 정해져 있지 않음 | 같은 상태를 앱 TTS와 화면 낭독 영역(liveRegion)이 함께 낸다. 녹음 중에도 화면 문구가 바뀐다 |
| 정지가 두 종류인데 이름이 하나 | "비상 정지"는 터치브릿지 움직임만 멈춘다. 가전 조리를 취소하려면 가전 취소 버튼(BT-06)을 눌러야 하는데, 앱에는 이 기능이 따로 없다 |

## 2. 원칙

1. **화면마다 같은 순서로 읽힌다**: 현재 기기 → 현재 상태 → 할 수 있는 행동.
2. **일반 버튼은 한 번에 실행한다**(TalkBack에서는 기본 두 번 탭). 앱 자체 "한 번 더 누르기"는 없앤다.
3. **모든 가전 실행은 이름이 분명한 '실행'·'취소' 버튼으로 확인한다.** 음성으로 "네"·"아니요"라고 답해도 된다. 예외는 두지 않는다.
4. **정지는 확인 없이 바로 요청한다.** '터치브릿지 정지'와 '조리 취소'는 이름과 동작을 나눈다.
5. **한 사건은 한 채널로 안내한다.** 마이크가 열려 있는 동안에는 아무것도 읽지 않는다.

## 3. 화면 흐름: 현재와 제안

```
현재
홈(좌우 넘기기 카드) ─┬─ 말하기 → 음성 화면(마이크 두 번 누르기, 예시 칩) ─┬─ 즉시 실행 → 누르는 중 → 남은 시간(3초 길게 눌러 정지) → 완료
                     │                                                 └─ "예" 음성 확인 → …
                     └─ 길게 누르기/카드 → 제어 방식 메뉴(음성·이미지·코스·숫자·매핑)
설정 탭: 사용자 설정 + 기기 추가 + 하드웨어 + 개발자 + 지표

제안
홈 ── 말하기 ── 듣기 ── 실행 확인 ── 전달 중 ── 남은 시간 ── 결과
 │     (세로 목록)        (실행·취소)  (정지 맨 앞) (조리 취소)
 ├─ 직접 선택(숫자 패드·간편 코스) ── 실행 확인 ── …
 └─ 관리(기기 추가, 위치 맞추기, 설정, 개발자 도구[숨김])
```

## 4. 화면별 구성

읽는 순서대로 적었다. "안내"는 그 화면에서 누가 무엇을 말하는지다. TalkBack이 켜져 있으면 화면 낭독이 기본 담당이고, 앱 TTS는 결과와 비상만 맡는다.

### 홈
- 제목: "터치브릿지"
- 기기 목록(세로): "전자레인지, 연결됨" / "세탁기, 연결 안 됨". 선택하면 그 기기가 현재 기기가 된다.
- 큰 버튼: **말하기**, **직접 선택**
- 아래: **관리**
- 안내: 처음 열 때만 앱 TTS로 "전자레인지가 선택되어 있습니다. 말하기를 누르세요." TalkBack이 켜져 있으면 생략하고 첫 포커스를 '말하기'에 둔다.
- 바뀌는 점: 좌우 넘기기를 없앤다(Lookout도 같은 이유로 가로 메뉴를 세로 목록으로 바꿨다, 7절). 길게 누르기로 여는 메뉴도 없앤다.

### 듣기
- 상태: "듣는 중" 한 줄. 마이크가 실제로 열리면 짧은 소리와 진동을 낸다.
- 버튼: **그만 듣기**, **도움말**(예시 명령은 여기서 듣는다)
- 안내: 마이크가 열려 있는 동안 화면 문구를 바꾸지 않고 liveRegion도 쓰지 않는다. 앞선 안내 음성이 끝난 뒤 마이크를 연다. TalkBack 낭독이 끝났는지는 앱이 알 수 없으므로, TalkBack이 켜져 있으면 짧은 대기를 두고 실기에서 길이를 정한다.
- 바뀌는 점: 마이크 두 번 누르기와 예시 칩을 화면에서 뺀다.

### 실행 확인
- 문장: "전자레인지에 30초 명령을 보낼까요?" 앱이 이해한 내용을 그대로 말한다.
- 버튼: **실행**, **취소**. 음성 "네"·"아니요"도 받는다.
- 안내: 진입 시 문장을 앱 TTS(result)로 한 번 말하고, 첫 포커스를 문장에 둔다.
- **모든 가전 실행이 이 화면을 거친다**(9절 결정 ①). "30초 돌려줘"처럼 명확한 명령도 예외가 아니다. 이해한 내용을 읽어 주는 것과 실행 동의를 받는 것은 다르다. 지금 코드의 "시간+요청 문법 전체 일치면 즉시 실행" 경로는 재설계 때 없앤다.

### 전달 중
- 첫 포커스: **터치브릿지 정지** (확인 없음, 단일 탭)
- 상태: "30초 버튼을 누르는 중" → "시작 버튼을 누르는 중"
- 안내: 단계가 바뀔 때 한 채널로만 말한다. 기다림이 길면 진행 소리를 낸다(Be My Eyes가 연결을 기다리는 동안 연결음을 들려주는 것과 같은 목적, 7절).
- 결과: ACK가 있으면 "누르기를 마쳤습니다", 없으면 "전달했지만 확인하지 못했습니다".

### 남은 시간
- 상태: "설정 시간 기준 남은 시간 2분 30초". 앱 시간이지 가전 상태가 아니다.
- 버튼: **조리 취소**(가전 취소 버튼을 대신 누른다, 조건은 아래), **남은 시간 듣기**, **홈**
- 음성: "얼마나 남았어", "취소해", "멈춰"
- 바뀌는 점: 3초 길게 누르기를 없앤다. 이 화면에서 터치브릿지는 이미 멈춰 있으므로, 사용자에게 필요한 것은 '조리 취소'다.

**조리 취소를 보여 주는 조건** (결정 ②)
- 그 기기에 **취소 버튼 매핑이 등록되어 있다.** BT-06을 모든 기기의 공통 취소로 가정하지 않는다. 기기별 매핑에 "취소" 역할 버튼이 없으면 이 버튼을 보이지 않고 "이 기기에는 취소 버튼이 등록되어 있지 않습니다"라고 말한다.
- 기기가 연결되어 있고, 위치 보정이 무효화되지 않았다(`calibrationInvalidated`가 아님).
- 직전 정지·실패 원인이 연결 끊김, 위치 오류, 기기 오류(FAULT)가 아니다. 이런 경우에는 추가 이동이 위험할 수 있으므로 조리 취소 대신 "기기를 확인해 주세요"를 안내한다.
- 조리 취소는 가전 버튼을 누르는 동작이므로 실행 확인 화면을 거친다(결정 ①). "조리를 취소할까요?" → 실행·취소.
- 결과 문구는 확인 근거에 따라 세 단계로 나눈다. 단계를 넘어 말하지 않는다.

  | 받은 근거 | 안내 |
  |---|---|
  | BLE 전송 성공, 이동 완료, Bot 명령 수락(OK) | "취소 버튼을 누르도록 명령을 보냈습니다. 가전이 멈췄는지 확인해 주세요." |
  | 실제 누름 완료를 감지한 응답 | "취소 버튼을 눌렀습니다. 가전이 멈췄는지 확인해 주세요." |
  | 가전이 멈췄다는 근거(예: CT 전력이 꺼짐 기준 아래로 유지) | "가전 전원이 꺼진 것으로 보입니다." 같은 관찰 표현. 전력 값은 안전 판단에 쓰지 않는다는 기존 계약을 따른다 |

  - 펌웨어 v4의 Bot OK는 명령 수락이지 패널이 눌렸다는 감지가 아니다(`CLAUDE.md` 하드웨어 절). 지금은 누름 완료를 감지하는 응답이 없으므로 **항상 첫째 줄 문구를 쓴다.**
  - 누름 완료와 가전 조리 중단은 계속 구분한다. "조리가 취소됐습니다"라고는 하지 않는다.

### 결과
- 확인된 것과 확인되지 않은 것을 나눠 말한다.
  - 정지(조리 취소 조건 충족): "터치브릿지를 멈췄습니다. 조리를 취소하려면 조리 취소를 누르세요."
  - 정지(조건 미충족): "터치브릿지를 멈췄습니다. 가전 상태를 확인해 주세요."
  - 시간 종료: "설정한 시간이 지났습니다. 가전이 멈췄는지 확인해 주세요."
- 버튼: **조리 취소**(남은 시간 화면과 같은 조건일 때만), **다시 듣기**, **홈**
- Envision처럼 핵심 한 문장만 먼저 말하고, 자세한 내용은 '다시 듣기'로 듣게 한다.

### 관리
- 기기 추가(음성 안내형), 위치 맞추기(보호자), 설정(음성·글씨), 개발자 도구(개발자 모드를 켰을 때만 보임)
- 시각장애인도 들어갈 수 있다. 다만 사진 위치 맞추기는 보는 사람이 하는 작업이라고 화면에서 분명히 말한다.
- 사진 보정을 시각장애인이 하려면 Seeing AI처럼 "네 모서리가 다 보이게" 소리로 안내하는 방식이 필요하다. 별도 과제로 둔다.

## 5. 확인 방식 통일

| 동작 | 방식 |
|---|---|
| 화면 이동, 마이크, 듣기 | 한 번 실행(TalkBack 기본 두 번 탭 = 앱 한 번) |
| 가전 버튼 누르기 | 실행 확인 화면의 **실행**·**취소** 또는 음성 "네"·"아니요" |
| 삭제처럼 되돌릴 수 없는 작업 | 확인 대화상자 **삭제**·**취소** |
| 터치브릿지 정지 | 확인 없이 바로. 모든 실행 화면에서 첫 포커스 |
| 조리 취소 | 가전 버튼을 누르므로 실행 확인 화면(실행·취소). 4절 조건을 만족할 때만 제공 |

TalkBack 사용 여부와 무관하게 같은 규칙을 따른다(결정 ③). 앱 자체 두 번 누르기(20초 대기)는 모든 화면에서 없앤다. 일반 버튼의 활성화와 가전 실행 확인은 다른 단계로 나눈다.

## 6. 안내 담당

원칙만으로는 중복이 없어지지 않는다. 결과 문장이 liveRegion에도 있으면 TalkBack과 앱 TTS가 같은 문장을 각각 읽는다. 그래서 **안내 항목마다 자동 낭독 담당을 하나로 정한다.** 담당이 아닌 쪽은 그 문장을 자동으로 읽지 않는다. 구체적으로는 liveRegion을 끈다.

**자동 낭독을 줄이는 것과 접근성 정보를 지우는 것은 다르다.** 현재 기기, 현재 상태, 마지막 결과 문장은 화면 글자와 시맨틱 트리에 항상 남긴다. 사용자가 TalkBack으로 화면을 다시 훑으면 언제든 읽을 수 있어야 한다. 그래서 상태·결과 문장에는 `ExcludeSemantics`를 쓰지 않는다. `ExcludeSemantics`는 같은 글자가 한 노드 안에서 두 번 읽히는 경우(라벨과 자식 글자가 같을 때)에만 쓴다.

| 안내 | TalkBack 켜짐 | TalkBack 꺼짐 | 화면 글자 |
|---|---|---|---|
| 화면 진입(화면 이름) | TalkBack(제목 heading) | 앱 TTS | 보임, 낭독 대상 |
| 홈 첫 안내 | 생략, 첫 포커스로 대신 | 앱 TTS | — |
| 마이크 열림·닫힘 | 소리·진동 | 소리·진동 | 보임, 탐색하면 읽힘, liveRegion 아님 |
| 녹음 중 상태 | 없음 | 없음 | 보임, 탐색하면 읽힘, liveRegion 아님 |
| 실행 확인 질문 | 앱 TTS(result) | 앱 TTS | 보임, 첫 포커스, liveRegion 아님 |
| 전달 단계(누르는 중) | 앱 TTS(result) | 앱 TTS | 보임, 탐색하면 읽힘, liveRegion 아님 |
| 전달 결과(성공·미확인·실패) | 앱 TTS(result) | 앱 TTS | 보임, 탐색하면 읽힘, liveRegion 아님 |
| 정지 결과 | 앱 TTS(emergency) | 앱 TTS | 보임, 탐색하면 읽힘, liveRegion 아님 |
| 남은 시간 구간 알림 | 앱 TTS(result) | 앱 TTS | 값은 포커스 시 TalkBack이 읽음 |
| BLE 연결 끊김·재연결 | 앱 TTS(result) | 앱 TTS | 배너, 탐색하면 읽힘, liveRegion 아님 |

이 표는 가정이다. 실기에서 앱 TTS와 TalkBack이 서로 끊는지, 앱 TTS 대신 `SemanticsService.announce`가 나은지 확인한 뒤 항목별로 고친다. 확인 전까지는 "중복 없음"이라고 말하지 않는다.

## 7. 참고한 앱

**공식 자료에서 확인한 사실**과 **터치브릿지에 적용하려는 제안**을 나눴다. 이 앱들은 정보를 읽거나 도움을 연결하는 앱이다. 실제 가전을 움직이는 터치브릿지의 실행 확인과 정지는 별도로 검증해야 한다.

| 앱 | 확인한 사실 | 제안 |
|---|---|---|
| Google Lookout | 가로로 스크롤되던 하단 탐색이 두 손가락으로 스크롤하는 스크린리더 사용자에게 어려워, 세로 목록 탐색 서랍으로 바꿨다. 앱 음성이 스크린리더 음성과 공존해야 한다고 적었다. ([Evolving Lookout](https://design.google/library/google-lookout-design-accessibility)) | 홈 기기 선택을 세로 목록으로 바꾼다. 안내 담당을 화면 설계 단계에서 정한다 |

## 8. 구현 순서

1. 안내 담당 정리와 녹음 중 무음(6절). 실기 TalkBack 확인과 같이 한다.
2. 실행 확인 화면과 앱 두 번 누르기 제거(5절).
3. '조리 취소' 기능. 기기별 매핑에 취소 역할을 지정하는 방법부터 만들고, 기존 누르기 경로와 정지 토큰 규칙을 그대로 따른다. 하드웨어에서 확인한다.
4. 홈 세로 목록과 관리 영역 분리.
5. 남은 시간·결과 화면 정리.
6. 시각장애인 당사자 과업 평가(`docs/USER_VALIDATION_PLAN.md`)로 확인한다. 눈을 감고 써 보는 점검은 사전 점검일 뿐이다.

## 9. 결정 (2026-11-10)

① **모든 가전 실행은 명시적으로 확인한다.** "전자레인지에 30초 명령을 보낼까요?" → 실행·취소 또는 음성 네·아니요. 안내 후 무확인 실행 예외는 두지 않는다. 빠른 실행이 필요한지는 사용자 과업 평가에서 확인한 뒤 다시 검토한다.
  - **구현(2026-11-10):** 음성 화면이 가전 실행 명령을 모두 "…실행할까요?"로 묻고 '실행'·'취소' 버튼(음성 네·아니요)으로 답을 받는다. 예시 명령 칩의 두 번 누르기는 이 확인과 겹쳐 없앴다. 백엔드 판정은 그대로 두고 앱에서 막는다. 위젯 테스트로 확인했고 실기 확인은 아직이다.

② **터치브릿지 정지 뒤 조리 취소를 자동으로 누르지 않는다.** 정지 원인이 연결 문제, 위치 틀어짐, 기계 이상이면 추가 이동이 위험할 수 있다. 조리 취소는 4절 조건(기기별 취소 매핑, 연결, 위치 보정, 정지 원인)을 만족할 때만 제공한다. BT-06을 공통 취소 버튼으로 고정하지 않는다.

③ **앱 자체 두 번 누르기를 TalkBack 사용 여부와 무관하게 없앤다.** 일반 버튼은 한 번에 동작하고, 가전 실행은 별도 확인 단계에서 정한다. 정지는 추가 확인 없이 요청한다.
