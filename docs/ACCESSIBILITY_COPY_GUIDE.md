# Touch Bridge 접근성 문구/TTS 가이드

> 작성일: 2026-06-25
> 목적: 시각장애인/저시력 사용자가 화면을 보지 않고도 모든 흐름을 이해할 수 있도록 TTS·햅틱·오류 문구의 원칙과 화면별 추천 문구를 정리한다.
> 관련 문서: [ACCESSIBILITY_REDESIGN_PLAN.md](ACCESSIBILITY_REDESIGN_PLAN.md), [MAPPING_VOICE_STABILIZATION_TODO.md](MAPPING_VOICE_STABILIZATION_TODO.md)

## 1. TTS 문장 원칙

1. **구조**: 화면/상태 이름 → 현재 상태 → 가능한 다음 행동 1개. 한 번에 여러 선택지를 늘어놓지 않는다.
2. **길이**: 한 문장은 가능하면 20자 내외, 최대 2문장. 화면을 안 보는 사용자는 긴 문장을 끝까지 기억하기 어렵다.
3. **능동형**: "~됩니다"보다 "~합니다/~하세요"처럼 행동 중심으로 말한다. ("연결이 완료되었습니다" → "기기에 연결했습니다")
4. **숫자는 단위까지 말한다**: "30초", "3번째 기기"처럼 단위를 생략하지 않는다.
5. **모호한 대명사 금지**: "이것", "그것", "여기" 대신 구체적 명사를 쓴다.
6. **위험/실패는 가장 먼저, 가장 짧게**: 위험·오류 안내는 문장 맨 앞에 배치하고 수식어를 뺀다.
7. **반복 안내는 다르게**: 같은 화면에 머무를 때 동일 문장을 그대로 반복하지 않고, 침묵 1회차/2회차처럼 단계적으로 바꾼다.
8. **모든 TTS는 햅틱과 짝을 이룬다**: 소리만으로 끝나는 안내는 없어야 한다(중요 액션 기준).

## 2. 햅틱 피드백 원칙

| 상황 | 패턴 | 이유 |
|---|---|---|
| 첫 탭(선택/포커스) | 짧은 약한 진동(light) | 손가락이 맞는 요소에 닿았음을 알림 |
| 둘째 탭(실행 확정) | 짧은 중간 진동(medium) + 실행 TTS | 오작동 방지 이중 확인 패턴과 일치 |
| 정상 완료 | 짧은 성공 진동 1회 | 실행이 끝났다는 신호 |
| 실패/오류 | 강한 진동 1회 또는 짧게 2연속 | 정상 완료와 구분되게 강도/패턴을 다르게 |
| 위험/비상 정지 | 강한 진동 + 즉시 TTS, 다른 안내보다 항상 우선 출력 | 생명/안전과 직결되므로 최우선 |
| 침묵/타임아웃 | 약한 진동 1회 + 안내 | 화면이 멈춘 게 아니라 입력을 기다린다는 신호 |

원칙: 강도 3단계(약/중/강)만 쓰고, 의미를 항상 동일하게 매핑한다. 강도가 곧 "위험도"를 뜻하게 해야 사용자가 패턴을 외울 수 있다.

## 3. 위험/오류 안내 원칙

1. **무엇이 실패했는지보다 "지금 무엇을 하면 되는지"를 먼저 말한다.** 원인은 그 다음.
2. **재시도 경로를 항상 같이 제시한다.** "실패했습니다"로 끝내지 않는다.
3. **위험 동작(가전 작동, 비상 정지 해제 등)은 실행 전 반드시 확인 문장을 거친다.**
4. **연속 실패(2회 이상)는 다른 문구로 전환한다.** 동일 안내 반복은 사용자에게 "고장났다"는 인식을 준다.
5. **비상 정지는 모든 안내보다 우선 출력되고, 끝까지 다른 TTS에 끼어들지 않는다.**

## 4. 화면별 추천 TTS 문구

### 4.1 화면 진입 안내 (공통 패턴)
- 홈 진입(기기 있음): `"홈입니다. 현재 전자레인지가 연결되어 있습니다. 말하기 버튼을 눌러 명령하세요."`
- 홈 진입(기기 없음, 사용자 모드): `"홈입니다. 등록된 기기가 없습니다. 보호자에게 기기 추가를 요청하세요."`
- 홈 진입(기기 없음, 보호자 모드): `"홈입니다. 등록된 기기가 없습니다. 기기 관리에서 추가할 수 있습니다."`
- 설정 진입: `"설정입니다. 음성 속도, 글자 크기, 보호자 모드를 변경할 수 있습니다."`
- 비상 정지 화면 진입: `"비상 정지입니다. 3초간 누르면 즉시 멈춥니다."`

### 4.2 홈 화면 안내
- 기기 전환 시: `"전자레인지로 전환했습니다. 연결 상태는 정상입니다."`
- 기기 상태 비정상: `"전자레인지 연결이 끊겼습니다. 다시 연결하려면 보호자 모드를 켜세요."`
- 활성 기기 없음, 여러 기기 보유: `"기기가 여러 개입니다. 먼저 사용할 기기를 선택하세요."`

### 4.3 기기 없음 상태 안내
- 사용자 모드: `"등록된 기기가 없습니다. 보호자에게 기기 추가를 요청하세요."`
- 보호자 모드 ON: `"등록된 기기가 없습니다. 기기 관리에서 새 기기를 추가하세요."`
- 추천 변경안(코드 미반영): 빈 상태 위젯(`home_empty_state.dart` 추정)에 보호자 모드 분기 TTS가 없다면, 위 두 문장을 상태값 기준으로 분기 출력하도록 추가 검토.

### 4.4 말하기 버튼 안내
- 버튼 포커스(첫 탭): `"말하기 버튼입니다. 누르면 음성 명령을 시작합니다."`
- 버튼 실행(둘째 탭/누르는 즉시 시작 구조라면 실행 시): `"듣고 있습니다. 명령을 말씀하세요."`
- 길게 눌러 취소 가능한 경우: `"음성 명령을 취소했습니다."`

### 4.5 음성 인식 시작/침묵/실패/재시도 안내
- 시작: `"듣고 있습니다. 명령을 말씀하세요."`
- 침묵 1회차: `"말씀이 들리지 않았습니다. 다시 말하려면 마이크를 누르세요."`
- 침묵 2회차 이상(같은 문장 반복 금지): `"여전히 들리지 않습니다. 화면을 닫고 다시 시도해 주세요."`
- 인식 실패(의도 불명확): `"명령을 이해하지 못했습니다. 기기 이름과 동작을 함께 말해 주세요."`
- 인식 성공, 실행 전 확인이 필요한 경우: `"전자레인지를 2분 동작합니다. 맞으면 한 번 더 눌러주세요."`
- 재시도 안내: `"다시 말하려면 말하기 버튼을 누르세요."`

### 4.6 비상 정지 안내
- 진입: `"비상 정지입니다. 3초간 누르면 즉시 멈춥니다."`
- 홀드 진행 중: `"멈추는 중입니다. 그대로 눌러주세요."` (진행률에 따라 1초 단위 갱신은 과도하므로 시작/완료만 음성, 중간은 진동으로 전달)
- 완료: `"즉시 중단했습니다. 기기가 멈췄습니다."`
- 음성 명령으로 트리거("멈춰"/"정지"/"그만"/"중단"/"stop"): `"중단 명령을 인식했습니다. 즉시 멈춥니다."` → 다른 모든 TTS보다 우선 출력.
- 기기 자체 이상 정지(GRBL `ALARM` 수신): `"기기가 안전을 위해 스스로 멈췄습니다. 보호자에게 확인을 요청하세요."` → 사용자에게 복구를 요구하지 않는다. 복구(`$X`/리셋)는 보호자·개발자 모드의 몫이다.

### 4.7 보호자 모드 ON/OFF 안내
- ON 전환: `"보호자 모드를 켰습니다. 기기 관리와 매핑에 접근할 수 있습니다."`
- OFF 전환: `"보호자 모드를 껐습니다. 기기 추가와 매핑은 숨겨집니다."`
- OFF 상태에서 보호자 전용 기능 접근 시도: `"이 기능은 보호자 모드에서만 사용할 수 있습니다. 설정에서 켜주세요."`

### 4.8 기기 추가/매핑/연결 안내 (보호자 모드 전제)
- 연결 화면 진입: `"기기 연결입니다. QR, 블루투스, NFC 중 하나를 선택하세요."`
- 스캔 중: `"주변 기기를 찾고 있습니다."`
- 연결 성공: `"전자레인지에 연결했습니다. 다음은 버튼 위치를 등록하는 매핑입니다."`
- 연결 실패: `"연결에 실패했습니다. 기기 전원과 거리를 확인한 뒤 다시 시도하세요."`
- 사진 매핑 시작: `"기기 사진을 찍으면 버튼 위치를 자동으로 분석합니다."`
- 매핑 저장 완료: `"버튼 위치 저장을 완료했습니다. 이제 음성으로 조작할 수 있습니다."`
- 수동 매핑 진입: `"수동 매핑입니다. 행과 열, 간격을 직접 입력합니다."`
- 좌표 테스트(테스트 터치) 실행 전: `"지정한 위치로 실제로 이동해 눌러 봅니다. 기기 주변에 손을 두지 마세요."`
- 좌표 테스트 후 확인: `"이 위치가 맞으면 저장을 누르세요. 다르면 위치를 다시 지정하세요."`

## 5. 금지해야 할 애매한 문구 예시

| 금지 표현 | 문제 | 대체 표현 |
|---|---|---|
| "오류가 발생했습니다" | 무엇을, 어떻게 해야 하는지 없음 | "연결에 실패했습니다. 다시 시도하려면 스캔 버튼을 누르세요." |
| "잠시만 기다려주세요" (얼마나? 무엇을?) | 종료 시점/행동 불명 | "기기를 찾고 있습니다. 5초 정도 걸립니다." |
| "여기를 눌러주세요" | "여기"가 화면 위치 지시라 무의미 | "말하기 버튼을 눌러주세요." |
| "처리 중입니다" | 무슨 처리인지, 끝나면 무슨 일이 일어나는지 불명 | "전자레인지에 명령을 전송하고 있습니다." |
| "문제가 있는 것 같습니다" | 추측형 표현, 확신 없는 안내는 불안감만 증폭 | "전자레인지 연결이 끊겼습니다." |
| "완료되었습니다" (무엇이?) | 행위 주체/대상 생략 | "버튼 위치 저장을 완료했습니다." |
| "다시 시도해주세요" (어떻게?) | 구체적 행동 누락 | "마이크 버튼을 다시 눌러 말씀해 주세요." |
| 동일 침묵 안내 무한 반복 | 고장 인식, 신뢰 하락 | 1회차/2회차 문구를 다르게, 2회차부터는 대안(화면 닫기 등) 제시 |

### 5-1. 기술 용어 금칙 (사용자 모드 기준)

| 금칙어 | 사용자 모드 대체 | 비고 |
|---|---|---|
| GRBL, G-code, 좌표 | 노출 금지. "동작"으로 표현 | 보호자 모드도 원칙적으로 노출 금지 |
| ALARM, 알람 상태 | "기기가 안전을 위해 스스로 멈췄습니다" | 개발자 로그에만 원문 표시 |
| error [n], 에러 코드 | "실행하지 못했습니다" + 재시도 경로 | 코드 번호는 개발자 로그 전용 |
| 홈 복귀, `$H` | "제자리로 돌아갑니다" | 보호자 모드 이상에서만 사용 |
| BLE, 페어링 | "연결" | 보호자 모드에서는 "블루투스 연결" 허용 |
| ESP, UART, 펌웨어 | 노출 금지 | 개발자 모드 전용 |

| 개발자 콘솔 / BLE 로그 / raw 명령 / 조이스틱 | ❌ | ❌ (기본) | ✅ |
| 음성 테스트 화면(독립 디버그용) | ❌ | ❌ (기본) | ✅ |
| 접근성 실험 지표(완료율/평균시간/비상정지/타임아웃) | ✅ (조회만) | ✅ | ✅ |

**각 모드에서 숨겨야 할 위험 기능**

- **사용자 모드에서 숨길 것**: 기기 추가/삭제, BLE/QR/NFC 연결, 매핑 화면 전체, 개발자 콘솔/raw 명령/조이스틱. 보호자 모드 토글만 노출하고 그 외 보호자 전용 동작은 진입 시 안내 후 차단.
- **보호자 모드에서도 기본 숨김(개발자 모드 별도 진입 필요)**: BLE 로그 원문, raw G-code/명령 전송, 조이스틱 직접 제어. 이 기능들은 실기기 디버깅용이라 일반 보호자가 실수로 가전을 오작동시킬 위험이 있음.
- **개발자 모드에서도 주의**: 비상 정지는 어떤 모드에서도 비활성화/숨김 대상이 아니다. 개발자 도구 진입 중에도 비상 정지 접근은 항상 유지해야 한다(추천 변경안: 개발자 콘솔류 화면에도 비상 정지 단축 접근이 있는지 확인 필요. 코드 미확인 상태라 단정하지 않음).

## 7. Semantics 라벨 / 스크린리더 병행 규칙

- 모든 조작 요소는 `Semantics` label과 hint를 갖는다. label은 대상 이름("비상 정지 버튼"), hint는 조작 방법과 결과를 설명한다.
- 이중 탭 요소의 hint에는 2단계 실행임을 명시한다. 스크린리더 더블탭 1회가 앱의 첫 탭으로 처리되는지 실기기 검증이 필요하다.
- 앱 자체 TTS와 VoiceOver/TalkBack 음성이 겹치는 화면은 어느 한쪽이 사용자 이해를 방해하지 않는지 확인한다.
- 추천 변경안: 스크린리더 활성 감지 시 앱 TTS를 축소하거나 핵심 안내만 남기는 정책을 실기기 테스트 후 결정한다.
- 장식용 아이콘/이미지는 시맨틱 트리에서 제외한다(`excludeSemantics`).
