# 보안

Touch Bridge는 근처의 다른 휴대폰이 장치에 명령을 보내 가전 버튼을 누르게 하는 상황을 막는 것을 목표로 한다. 이 문서는 구현한 보호 장치와 아직 남은 약점을 정리한다. 기준은 `hardware/touchbridge_corexy/`(펌웨어 v4)와 `lib/services/ble_security_session.dart`다.

## 구성과 신뢰 구간

```
휴대폰 앱 ──(BLE, HMAC 인증)──▶ ESP32 모터 제어기 ──(BLE)──▶ SwitchBot Bot(누름)
    │
    └──(HTTPS, API 키)──▶ 백엔드(FastAPI) ──▶ AI 모델
```

## 구현한 것

### 휴대폰 ↔ ESP32

- **키 등록(provision):** 공유 비밀(8자 이상)을 ESP32 NVS에 저장한다. 소스 코드에는 기본 비밀값이 없다.
- **세션 인증:** 앱이 `challenge`를 요청하면 ESP32가 난수(NONCE)를 돌려주고, 앱이 `HMAC_SHA256(secret, nonce)`로 `auth`를 보낸다. 검증에 성공하면 5분 동안 명령을 받는다.
- **물리 동작 차단:** 키가 등록된 장치는 인증되지 않은 세션의 이동·누름·설정 명령을 거부한다.
- **1회용 위치 토큰:** `move_only`로 목표 위치에 도착하면 장치가 `positionToken`을 발급한다. `press`는 이 토큰이 있어야 실행되고, 토큰은 한 번만 쓸 수 있다. 그 사이 위치가 밀렸으면 거부한다.
- **비상 정지 예외:** `stop`은 인증 없이 항상 실행한다. 인증 시간이 끝났거나 연결이 불안정할 때도 장치를 멈출 수 있어야 하기 때문이다.
- **키 교체:** 이미 등록된 키는 유효한 세션이나 USB 시리얼에서만 바꿀 수 있다.
- **로그:** 부팅·상태 로그에는 키 값이 아니라 등록 여부(`set`/`none`)와 세션 상태(`ok`/`locked`)만 남긴다.

### 앱 ↔ 백엔드

- 배포 앱은 HTTPS 주소만 허용한다.
- `BACKEND_API_KEY`가 설정되면 모든 요청에 `X-API-Key`를 요구한다.
- IP당 분당 요청 수를 제한한다(일반 60회, 사진 분석 10회). 업로드는 5MB까지 받는다.
- AI 응답은 스키마와 버튼 ID 화이트리스트로 검사한 뒤 앱에 돌려준다. 규칙 경로의 응답도 같은 검사를 거친다.

## 남은 약점

| 구간 | 내용 | 개선 방향 |
|---|---|---|
| ESP32 → SwitchBot Bot | Bot의 비밀번호 기능을 켜면 암호화된 명령만 받는데, 펌웨어가 이를 지원하지 않아 비밀번호를 끈 상태로 쓴다. 근처의 다른 기기도 Bot을 직접 누를 수 있다. | 암호화된 Bot 명령 지원 |
| 첫 키 등록 | 키가 없는 장치는 누구나 동작시킬 수 있고, 첫 키도 누구나 등록할 수 있다(trust on first use). | 보호자 설정에서 처음 한 번만 등록, 공장 초기화 절차 분리 |
| BLE 링크 | 페어링·암호화를 쓰지 않아 명령 내용이 평문이다. 명령별 MAC도 없다. | LE Secure Connections + bonding, 명령별 MAC·논스 |
| USB 시리얼 | 케이블을 꽂으면 인증 없이 모든 명령을 보낼 수 있고, `KEYRESET`으로 키를 지울 수 있다. | 배포용 펌웨어에서 시리얼 명령 비활성화 |
| 앱 API 키 | `.env`가 앱 asset에 포함되므로 `AI_BACKEND_API_KEY`를 비밀로 취급할 수 없다. | 서버가 발급하는 짧은 수명의 토큰으로 교체 |
| 속도 제한 | IP를 `request.client.host`로 판단해, 프록시 뒤에서는 모든 요청이 같은 IP로 보일 수 있다. | 신뢰 프록시 헤더 설정 |

## 시험 절차

1. 키 등록: 임시 비밀을 보내 `PROVISION_OK`를 받는다.
2. 인증: `challenge` → `auth` → `AUTH_OK`.
3. 정상 동작: `move_only`로 `POSITIONED`와 `positionToken`을 받고, 그 토큰으로 `press` → `COMPLETED`.
4. 거부: 인증 없이 `press`를 보내면 `AUTH_REQUIRED`로 거부되는지 확인한다.
5. 토큰 재사용: 같은 `positionToken`으로 다시 `press`를 보내면 `ERROR_INVALID_TOKEN`이 오는지 확인한다.
6. 비상 정지: 인증 없이 `stop`이 실행되는지 확인한다.
