# Touch Bridge GRBL (3-Axis 28BYJ-48 Stepper Control & Hardware Touch Bridge)

본 프로젝트는 오픈소스 CNC 펌웨어인 **GRBL v0.9**를 기반으로 개조되어, 저가형 유니폴라 스테퍼 모터인 **28BYJ-48**과 **ULN2003 드라이버**를 통해 XYZ 3축을 정밀 제어하고, 외부 시리얼 명령을 받아 물리 키패드나 터치스크린 등을 자동으로 조작할 수 있는 **"Touch Bridge (물리 터치 로봇 제어 시스템)"**의 임베디드 하드웨어/소프트웨어 통합 소스코드입니다.

이 프로젝트는 오픈소스 `ruizivo/GRBL-28byj-48-Servo`에서 포크되었으며, 서보 모터 대신 Z축 전체를 28BYJ-48 스테퍼 모터로 완전 전환하여 진정한 3축 CNC 좌표계 조작을 실현함과 동시에, 동적 그리드 변환 및 터치 모션 블로킹 제어 프로토콜을 결합시켰습니다.

### 주요 디렉토리 및 파일 상세 역할

1. **`grbl/` (개조된 GRBL v0.9 코어)**
   - 본 프로젝트의 심장부입니다. 표준 2축/3축 스텝-방향 신호를 유니폴라 모터의 4상 위상 신호(8스텝 시퀀스)로 변환해 아두이노 포트에 직접 가로채기 출력하는 래퍼 기법이 탑재되어 있습니다.
   - `stepper.c`에서는 유니폴라 모터의 고질적 결함인 대기 시 극심한 발열 문제를 해결하기 위해, 움직임이 멈춘 상태(`st_go_idle`)에서 즉각 모든 모터 구동 핀의 전압을 차단하는 **발열 방지 전류 차단(Safe Coils Idle)** 기술이 포함되어 있습니다.
   - `protocol.c`에서는 사용자가 송신한 물리적 터치 매트릭스 호출(`BTN_5`) 및 실시간 동적 격자 매개변수 설정(`SET_GRID`) 명령을 GRBL 버퍼가 소화하기 전에 먼저 가로채 정밀 이송 명령(G0/G1/G4)으로 복합 변환 및 하드웨어 동기화 처리를 지휘합니다.

2. **`doc/script/` (PC 측 제어 스크립트)**
   - 임베디드 기기와 시리얼(USB) 통신을 열고 CNC 좌표 명령 및 터치 커맨드를 원격으로 스트리밍하는 파이썬 코드들입니다.
   - 아두이노의 하드웨어 응답 속도와 수신 버퍼 제어를 완벽히 수행하여 통신 도중 데이터 유실 없이 대량의 G-code 및 특수 터치 매트릭스 동작을 막힘없이 실행할 수 있게 돕습니다.

3. **`grbl 0.8 with SpindleControl/` (레거시 코드)**
   - 스핀들 제어 기능이 포함되어 있던 기존 0.8 기반 소스들로, C++ 클래스 구조를 따르며, 현재 v0.9 C 기반 시스템으로의 포팅 연구 및 디버깅 시 레퍼런스로 활용됩니다.

## 1. 하드웨어 결선 정보 (Pinout & Connection)

28BYJ-48 스테퍼 모터는 5V 유니폴라 4상 8선(기어드 내부 결선으로 실제 5핀) 스텝 모터입니다. 이를 제어하기 위해 아두이노 우노(Arduino Uno - ATmega328p)와 ULN2003 드라이버 칩 보드 간의 핀 매핑은 아래와 같이 완벽히 구현되어 있습니다.

### 1.1 모터 및 드라이버 결선
각 축의 ULN2003 입력 핀(`IN1` ~ `IN4`)은 아두이노의 아래 디지털/아날로그 핀에 1:1로 정방향 대칭 연결해야 합니다.

| 축 (Axis) | ULN2003 입력 핀 | 아두이노 우노 핀 | AVR 포트 레지스터 | 비고 |
| :---: | :---: | :---: | :---: | :--- |
| **X축** | IN1 (Orange)<br>IN2 (Yellow)<br>IN3 (Pink)<br>IN4 (Blue) | **Digital 2**<br>**Digital 3**<br>**Digital 4**<br>**Digital 5** | `PORTD` (PD2)<br>`PORTD` (PD3)<br>`PORTD` (PD4)<br>`PORTD` (PD5) | IN1 $\rightarrow$ D2 ~ IN4 $\rightarrow$ D5 정방향 1:1 연결 |
| **Y축** | IN1 (Orange)<br>IN2 (Yellow)<br>IN3 (Pink)<br>IN4 (Blue) | **Analog A0**<br>**Analog A1**<br>**Analog A2**<br>**Analog A3** | `PORTC` (PC0)<br>`PORTC` (PC1)<br>`PORTC` (PC2)<br>`PORTC` (PC3) | IN1 $\rightarrow$ A0 ~ IN4 $\rightarrow$ A3 정방향 1:1 연결 |
| **Z축** | IN1 (Orange)<br>IN2 (Yellow)<br>IN3 (Pink)<br>IN4 (Blue) | **Digital 8**<br>**Digital 9**<br>**Digital 12**<br>**Digital 13** | `PORTB` (PB0)<br>`PORTB` (PB1)<br>`PORTB` (PB4)<br>`PORTB` (PB5) | **비연속 포트 주의!**<br>IN1 $\rightarrow$ D8, IN2 $\rightarrow$ D9,<br>IN3 $\rightarrow$ D12, IN4 $\rightarrow$ D13 연결 |

> [!WARNING]
> Z축 드라이버 결선 시 아두이노 핀이 비연속적(`D8`, `D9`, `D12`, `D13`)으로 구성되어 있습니다. `IN1~IN4` 단자를 순서대로 각각 `D8`, `D9`, `D12`, `D13`에 정확하게 개별 결선하십시오.

### 1.2 주변 장치 및 기타 핀 매핑
28BYJ-48 제어 핀 확보를 위해 기존 GRBL 표준 핀 중 일부가 변경/이설되었습니다.

* **Z축 리미트 스위치(Z-Limit)**: 기존 Digital 11(PWM 핀) 대신 **Analog Pin 5 (PC5)** 가상 비트로 이설되었습니다.
* **스핀들 PWM 제어(Spindle PWM)**: 하드웨어 PWM 타이머(OCR2A)를 활성화하기 위해 **Digital Pin 11 (PB3)**로 매핑됩니다.
* **제어 스위치(Control)**:
  * 리셋(Reset): **Analog Pin 0 (PC0)**
  * 피드 홀드(Feed Hold) / 안전 도어(Safety Door): **Analog Pin 1 (PC1)**
  * 사이클 스타트(Cycle Start): **Analog Pin 2 (PC2)**
* **프로브 핀(Probe)**: **Analog Pin 5 (PC5)** (공유 혹은 용도에 맞게 설정 확인 필요)

### 1.3 ESP32 무선 통신 브릿지 결선 가이드 (ESP32 WROOM-32U ↔ Arduino Uno)

Arduino Uno의 GRBL 펌웨어에 WiFi 및 블루투스(Bluetooth SPP) 통신을 탑재하기 위해 **ESP32 WROOM-32U**를 "무선-시리얼 바이패스 브릿지"로 결선합니다. GRBL의 타이머 인터럽트 충돌을 회피하기 위해 Uno는 안정적인 **하드웨어 시리얼(D0, D1)**을 그대로 유지하고, ESP32의 **UART2** 포트를 통해 연결합니다.

#### [물리 결선도]
```text
      [ESP32 WROOM-32U]                           [Arduino Uno]
┌──────────────────────────┐                 ┌──────────────────────────┐
│                      GND ├─────────────────┤ GND                      │
│                          │                 │                          │
│  GPIO 17 (TX2)           ├─────────────────┤ RX (Digital 0)           │
│                          │                 │                          │
│  GPIO 16 (RX2)  ◄──[R2]──┤ 3.3V 분배 노드   │                          │
│                   ▲      │                 │                          │
│                  [R1]    │                 │                          │
│                   │      │                 │                          │
│                  GND     │                 │ TX (Digital 1)           │
└──────────────────────────┘                 └──────────────────────────┘
```

#### [안전한 로직 레벨 변환 (5V ➔ 3.3V) 주의사항]
ESP32의 모든 GPIO는 **3.3V 로직 레벨**로 작동하는 반면, Arduino Uno는 **5V 로직 레벨**로 동작합니다.
* **ESP32 TX2 ➔ Uno RX0**: 3.3V 출력을 Uno가 High(3.0V 이상)로 안전하게 수신할 수 있어 **직접 1:1 결선**이 가능합니다.
* **Uno TX1 ➔ ESP32 RX2 (필수 보호)**: Uno의 5V 전압이 ESP32에 직접 유입되면 칩이 영구 손상됩니다. 아래와 같이 2개의 저항을 사용한 **분배 회로(레벨 시프터)**를 반드시 거쳐서 결선해야 합니다.
  * **회로 구성**: `Uno TX (D1)` ➔ `1kΩ 저항` ➔ `[ESP32 RX2 (GPIO16) 연결점]` ➔ `2kΩ 저항` ➔ `GND`

## 2. 핵심 기술적 특징 (Key Technical Features)

### 2.1 가상 포트 가로채기 Wrapper (`cpu_map.h`)
일반적인 GRBL은 Step/Direction 드라이버(A4988 등)를 향해 다이렉트 레지스터 쓰기(`PORTD`, `PORTB`)를 수행합니다. 28BYJ-48과 같은 유니폴라 모터는 4개 핀에 상 순서대로 위상(Phase) 신호를 직접 주어야 하므로 기존 GRBL 코어의 펄스 생성 로직과 충돌할 수 있습니다. 

이를 해결하기 위해 이 코드는 **가상 포트 맵핑(Virtual Port Wrapper)** 기술을 사용합니다.
```c
// cpu_map.h 내 가상 포트 구조 선언
uint8_t VPORTB;
uint8_t VPORTC;
uint8_t VPORTD;
uint8_t VDDRB;
...
#define STEP_PORT       VPORTD
#define DIRECTION_PORT    VPORTD
```
GRBL 코어(플래너 및 스텝 발생기)가 스텝을 생성하고 방향 포트 레지스터에 쓰기 명령을 내릴 때, 하드웨어 레지스터가 아닌 가상의 `VPORTB`, `VPORTC`, `VPORTD` 변수에 값을 기록하도록 우회(Hooking)합니다. 이로써 기존의 초정밀 가속도 제어 및 Bresenham 선형 보간 타이머 알고리즘을 손상시키지 않고 그대로 유지할 수 있습니다.

### 2.2 8스텝 유니폴라 여자 알고리즘 (`stepper.c`)
타이머 인터럽트인 `ISR(TIMER1_COMPA_vect)` 내에서 Bresenham 알고리즘에 의해 X, Y, Z축 중 스텝 이동 명령이 트리거될 때마다 가상 펄스 대신 **1-2상 여자 방식의 8스텝 시퀀스 테이블**을 타고 가며 물리 포트에 직접 위상 신호를 출력합니다.

각 축은 회전 방향(`direction_bits`)에 따라 `costyx`, `costyy`, `costyz` 인덱스를 `1 ~ 8` 범위 내에서 가감(순환) 연산하며 다음 비트 패턴을 출력합니다.

#### [X축 여자 테이블 (PORTD - D2~D5)]
* **1단계**: `0B100000` (PD5 / IN4)
* **2단계**: `0B110000` (PD5, PD4 / IN4, IN3)
* **3단계**: `0B010000` (PD4 / IN3)
* **4단계**: `0B011000` (PD4, PD3 / IN3, IN2)
* **5**: `0B001000` (PD3 / IN2)
* **6**: `0B001100` (PD3, PD2 / IN2, IN1)
* **7**: `0B000100` (PD2 / IN1)
* **8**: `0B100100` (PD5, PD2 / IN4, IN1)

#### [Y축 여자 테이블 (PORTC - A0~A3)]
* **1단계**: `0B1000` (PC3 / IN4)
* **2단계**: `0B1100` (PC3, PC2 / IN4, IN3)
* **3단계**: `0B0100` (PC2 / IN3)
* **4**: `0B0110` (PC2, PC1 / IN3, IN2)
* **5**: `0B0010` (PC1 / IN2)
* **6**: `0B0011` (PC1, PC0 / IN2, IN1)
* **7**: `0B0001` (PC0 / IN1)
* **8**: `0B1001` (PC3, PC0 / IN4, IN1)

#### [Z축 여자 테이블 (PORTB - D8, D9, D12, D13)]
* Z축은 배선 편의 및 핀 충돌 회피를 위해 아날로그 비트 스위칭이 다르게 결합됩니다 (B5, B4, B1, B0 매핑).
* **1단계**: `0B100000` (PB5 / IN4)
* **2단계**: `0B110000` (PB5, PB4 / IN4, IN3)
* **3단계**: `0B010000` (PB4 / IN3)
* **4단계**: `0B010010` (PB4, PB1 / IN3, IN2)
* **5**: `0B000010` (PB1 / IN2)
* **6**: `0B000011` (PB1, PB0 / IN2, IN1)
* **7**: `0B000001` (PB0 / IN1)
* **8**: `0B100001` (PB5, PB0 / IN4, IN1)

### 2.3 지능형 코일 전류 차단 (발열 방지 안전 장치)
> [!IMPORTANT]
> 28BYJ-48과 같은 유니폴라 스테퍼 모터는 일반적인 바이폴라 모터와 달리 드라이버 IC(ULN2003) 단에서 전류 자동 차단 기능이 없습니다. 정지 상태(Idle)에서도 특정 코일에 지속적으로 대전류가 흘러 **모터와 ULN2003 칩에 화상을 입을 수준의 극심한 발열**이 발생하게 됩니다.

이 코드에서는 이 치명적인 하드웨어적 결함을 소프트웨어 수준에서 정교하게 차단했습니다. 스테퍼가 모든 동작을 완료하고 대기 상태에 접어들어 `st_go_idle()` 함수가 호출되면, 즉각 **모든 관련 제어 핀의 출력을 강제로 LOW(0) 상태로 완전히 꺼버립니다.**
```c
// Touch Bridge: 28BYJ-48 발열 차단을 위한 코일 전류 즉각 차단
PORTD &= ~0x3C; // X축 (D2~D5) LOW
PORTC &= ~0x0F; // Y축 (C0~C3) LOW
PORTB &= ~0x33; // Z축 (B0,B1,B4,B5) LOW
```
이를 통해 장시간 CNC 시스템을 켜두거나 대기 상태를 유지하더라도 시스템의 온도 상승 및 전력 낭비를 완벽하게 예방하여 하드웨어 내구성을 획기적으로 상승시켰습니다.

## 3. Touch Bridge 소프트웨어 프로토콜 명세

시리얼 통신을 통해 모션 명령 및 환경 설정을 전송하는 독자적인 브릿지 프로토콜이 내장되어 있습니다. 이 명령들은 표준 GRBL의 파싱 루프가 시작되기 전 `protocol.c` 단에서 직접 가로채어 최단 시간에 반응합니다.

### 3.1 터치 매트릭스 실행 명령어 (`BTN_{Number}`)
정해진 격자 내의 특정 버튼 일련번호를 전송하여 해당 물리 위치로 이동해 콕 누르고 오는 핵심 매커니즘입니다.

* **수신 명령어 예시**: `BTN_5` (5번 버튼 터치 실행)
* **성공 응답 예시**: `TOUCH_OK:BTN_5\r\n` (터치 시퀀스 완전 완료 시 피드백 전송)

#### [동작 시퀀스 및 처리 과정]
1. 수신된 문자열에서 버튼 번호(예: 5)를 정수로 파싱합니다.
2. 현재 활성화된 동적 그리드 매개변수(`grid_cfg`)를 바탕으로 행(Row)과 열(Col)을 계산합니다.
   $$\text{Index} = \text{Button Number} - 1$$
   $$\text{Col} = \text{Index} \pmod{\text{grid\_cfg.cols}}$$
   $$\text{Row} = \text{Index} / \text{grid\_cfg.cols}$$
3. 해당 버튼의 절대 XYZ 좌표를 산출합니다.
   $$X_{\text{target}} = \text{grid\_cfg.origin\_x} + (\text{Col} \times \text{grid\_cfg.pitch\_x})$$
   $$Y_{\text{target}} = \text{grid\_cfg.origin\_y} + (\text{Row} \times \text{grid\_cfg.pitch\_y})$$
4. **G-code 인터프리터 (`gc_execute_line`) 직접 호출 루틴**:
   * **절대좌표 모드 셋업**: `G90`
   * **목표 좌표 고속 이동**: `G0 X{x} Y{y}` (부동소수점 오차 및 런타임 캐스팅 부하를 극복하고자 정수부와 소수부를 수학적으로 분리하여 텍스트 빌드 처리)
   * **Z축 누름 모션**: `G1 Z-5.0 F150` (Z축을 5.0mm만큼 아래로 밀며, 최적 피드레이트인 F150 유지)
   * **접점 밀착 유지 대기**: `G4 P0.3` (바운싱 방지 및 확실한 터치를 위해 0.3초 동안 그 자리에 머무름)
   * **안전 높이 복원**: `G0 Z0.0 F150` (Z축을 안전 높이 0.0mm로 이송하여 부품 파손 방지)
5. `protocol_buffer_synchronize()`를 호출하여 위 비동기 모션 계획이 하드웨어에서 물리적으로 완전히 완료될 때까지 메인 통신 루프를 동기적으로 블로킹 대기합니다.
6. 모션 완료 시 `TOUCH_OK:BTN_{ID}` 신호를 시리얼 전송하여 마스터 컨트롤러에 작업 성공을 통보합니다.

### 3.2 동적 그리드 변환 명령어 (`SET_GRID ...`)
터치 대상 기기의 사양(버튼의 크기, 기기 변경 등)이 바뀔 경우 기기를 분해하거나 재컴파일할 필요 없이 실시간 시리얼 코맨드로 좌표 그리드를 재배치할 수 있는 고급 기능입니다.

* **수신 명령어 형식**:
  `SET_GRID {rows} {cols} {origin_x*10} {origin_y*10} {pitch_x*10} {pitch_y*10}`
* **성공 응답**: `GRID_CONFIG_UPDATED\r\n`
* **에러 응답**: `ERROR:Invalid format...`

> [!NOTE]
> 부동소수점(`float`) 데이터 파싱은 8비트 아두이노 MCU에 매우 무거운 연산이며 시리얼 전송 과정에서 문자 오차를 겪기 쉽습니다. 따라서 본 프로토콜에서는 **실제 물리값에 10배를 곱한 정수(Decimal * 10)**를 전송하도록 규격화하여 MCU 연산 부하를 최소화하고 완벽한 해상도를 보장합니다.

* **입력 예시**: `SET_GRID 3 3 0 0 200 200`
  * 행 개수: 3행 / 열 개수: 3열 (총 9개 터치 패드 타겟 설정)
  * 시작 절대 좌표 (Origin X, Y): (0.0mm, 0.0mm)
  * 버튼 간 X, Y 간격 (Pitch X, Y): 200 / 10 = 20.0mm 간격 격자망 형성

### 3.3 무선 네트워크 및 블루투스 연동 가이드

ESP32 브릿지 펌웨어가 성공적으로 업로드 및 부팅되면, 다음과 같이 두 가지 무선 제어 채널이 동시에 활성화됩니다.

#### [블루투스 제어 채널 (Bluetooth Classic SPP)]
* **디바이스 이름**: `Touch_Bridge_CNC`
* **접속 방법**:
  1. 제어용 스마트폰 또는 PC의 블루투스를 켭니다.
  2. 기기를 검색하여 `Touch_Bridge_CNC`와 페어링합니다.
  3. 시리얼 블루투스 터미널 앱(예: Serial Bluetooth Terminal)에서 해당 기기로 무선 직렬 접속합니다.
  4. 연결 직후 Uno GRBL의 웰컴 메시지가 수신되면 정상 연동된 상태입니다.

#### [와이파이 제어 채널 (WiFi AP & TCP 소켓)]
* **WiFi AP SSID (자체 핫스팟)**: `Touch_Bridge_CNC_WiFi` (비밀번호 없음, 개방형)
* **ESP32 기본 IP**: `192.168.4.1`
* **TCP 소켓 대기 포트**: `8080`
* **접속 및 스트리밍 방법**:
  1. PC나 스마트폰의 와이파이 목록에서 `Touch_Bridge_CNC_WiFi` 무선망에 연결합니다.
  2. TCP 클라이언트 터미널 프로그램(예: Hercules, Netcat 등) 또는 스트리머 파이썬 스크립트(`stream.py`)를 실행합니다.
  3. 대상 주소를 `192.168.4.1`로, 포트 번호를 `8080`으로 입력하고 소켓 연결(Connect)을 수립합니다.
  4. 소켓을 통해 `?`나 `BTN_5` 같은 G-code 및 터치 명령을 전송하면 무선 와이파이를 경유해 Uno로 바이트 손실 없이 고속 바이패스 송신됩니다.

## 4. 빌드 및 펌웨어 업로드 (Compile & Upload)

본 펌웨어는 표준 AVR-GCC 툴체인을 통해 가볍고 컴팩트하게 빌드되며 Makefile이 정교하게 작성되어 있습니다.

### 4.1 CLI 빌드 (Makefile 기반)
PC에 `avr-gcc`, `avrdude`가 설치되어 있는 경우 워크스페이스의 루트 경로에서 다음 명령을 실행합니다.

```bash
# 코드 컴파일 및 grbl.hex 파일 생성
make clean
make all

# 아두이노 우노에 펌웨어 직접 업로드 (프로그래머가 avrisp2 등인 경우)
make flash

# 퓨즈 비트 확인 및 업로드
make fuse
```
