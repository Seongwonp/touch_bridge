# Touch Bridge CT 노드

DFRobot SEN0211로 가전 전류를 재서 모터 ESP32(`hardware/touchbridge_corexy/`)로 1초마다 보고한다.
보드는 FireBeetle ESP32, 빌드 환경은 `firebeetle32_adc`뿐이다.

2026-11-10에 4MB ESP32 두 대(이 노드와 모터 ESP32)에서 ESP-NOW로 보고가 오가는 것을 확인했다(부하 0 W 상태).
`src/ct.cpp`, `src/ct.h`는 검증된 콘센트 펌웨어에서 수정 없이 가져왔다. 릴레이와 비상정지 입력은 뺐다.

## 활선 안전 경고

**클램프는 활선 한 가닥에만 건다. 피복을 벗긴 활선을 다루는 작업은 감전·화재 위험이 있다.**
반드시 플러그를 뽑은 상태에서 결선하고, 노출부를 절연한 뒤 전원을 넣는다. 전원선 전체를 물리면
전류가 상쇄되어 0으로 나온다. 혼자 작업하지 말고, 자신이 없으면 절연된 측정용 분기 어댑터를 쓴다.

## 무선 연결 (ESP-NOW, 기본)

`include/config.h`의 `CT_LINK_ESPNOW`가 1이면 보고 줄을 ESP-NOW 브로드캐스트로도 보낸다. 채널은
`CT_ESPNOW_CHANNEL`(1)이며 모터 ESP32의 같은 이름 값과 맞아야 한다. 이 경우 아래 결선은 필요 없다.
Wi-Fi AP에는 접속하지 않는다.

## 배선 (유선 예비)

선 3개를 **교차**해서 잇고, 두 보드의 **GND를 반드시 묶는다**. 두 보드 모두 3.3V 로직이다.

| CT 노드 | 모터 ESP32 | 비고 |
|---|---|---|
| GPIO17 (TX2) | GPIO21 (RX) | 보고 데이터 |
| GPIO16 (RX2) | GPIO22 (TX) | 예비선. 지금은 보내는 데이터가 없다 |
| GND | GND | 공통 접지 필수 |

**모터 ESP32의 GPIO16·17은 엔코더 입력이다. 이 선을 거기에 꽂지 말 것.**

| SEN0211 | CT 노드 |
|---|---|
| `+` | 3.3V |
| `-` | GND |
| `A` | GPIO36 (ADC1) |

## 보고 형식

115200 8N1, 1초에 한 줄.

```json
{"t":"ct","w":812.5,"a":3.69,"seq":42}
```

`w`, `a`는 추정값이다. 전압은 재지 않고 220V, 역률 1.0으로 가정한다. 창이 부족하면 줄을 보내지 않으며,
받는 쪽은 끊김을 "모름"으로 처리한다. USB 시리얼에도 같은 줄이 나가므로 시리얼 모니터로 점검할 수 있다.

## 빌드

```bash
pio run -e firebeetle32_adc
```

4MB 플래시 보드(일반 ESP32 DevKit)에 올릴 때는 `platformio.ini`의 `board`를 `esp32dev`로 바꿔 빌드한다.

## 측정 전 미확정 값

- 켜짐·꺼짐 판정 기준(100 W 5초 / 15 W 3초)은 2026-11-02 전자레인지 측정(별도 장치)에서 가져왔다.
  `hardware/touchbridge_corexy/config.h`에서 바꾸며, 가전마다 다시 잴 수 있다.
- `include/config.h`의 `CT_CAL_GAIN_CH`(보정 배율)는 아는 부하로 맞춰야 한다.
- 내장 ADC는 보드마다 편차가 있어 켜짐·꺼짐 판단용이지 정밀 계측용이 아니다.
- 1초 창 평균은 이번에 정한 값이며 원본의 100ms 창과 다르다. 실측으로 확인해야 한다.
